# Dataset v1 — schema contract

**Version:** `1.0.0` · **Owner:** Ledger · **Consumers:** the site generator and the keyed API (Forge, ARC-4)

## What one row is

**One row is one obligation: a single jurisdiction × regime × direction × size band, and the date it starts.**

That is the unit deliberately. Germany does not get one row — it gets one row for *receiving* (starts 2025‑01‑01, no threshold), one for *issuing above* the €800k turnover line (2027‑01‑01) and one for *issuing at or below* it (2028‑01‑01). A single "Germany: 2025" row would be wrong for almost every reader.

Consequences for a consumer:

- A country page is a **filter over rows**, never a lookup of one row.
- Two rows in the same jurisdiction and regime may carry different dates without contradicting each other, as long as their `direction` or threshold differs. `obligation_id` is what must be unique.
- A jurisdiction being absent from `rows` means **not yet recorded**, not "no obligation". Never render absence as "none".

## File envelope

```json
{
  "schema_version": "1.0.0",
  "generated_from": "...",
  "generated_on": "YYYY-MM-DD",
  "row_count": 4,
  "coverage": { ... },
  "rows": [ { ...row... } ]
}
```

`coverage` is the honest-numbers block, and it is the only place public coverage claims may come from:

| field | type | meaning |
| --- | --- | --- |
| `jurisdictions` | string[] | ISO 3166‑1 alpha‑2 codes actually present |
| `jurisdiction_count` | int | length of the above |
| `regimes` | string[] | regime slugs present |
| `confidence_counts` | object | count of rows at `verified` / `reported` / `unknown` |
| `oldest_checked_on` | date | **the staleness number.** Quote this with any coverage claim |
| `newest_checked_on` | date | |
| `rows_with_open_unknowns` | int | rows whose `unknowns` array is non‑empty |
| `note` | string | scope caveat in plain English |

## Row fields

Required on every row. `null` is permitted only where the column says so; a missing key is a schema violation, not an empty value.

### Identity

| field | type | notes |
| --- | --- | --- |
| `obligation_id` | string | Stable primary key. `{JURISDICTION}-{regime}-{direction}-{band-slug}`. Never reused, never renamed without a CHANGELOG entry. |
| `jurisdiction` | string | ISO 3166‑1 alpha‑2, uppercase |
| `jurisdiction_name` | string | English display name |
| `regime` | string | kebab-case slug, e.g. `e-invoicing-b2b` |
| `regime_label` | string | Human label for a page heading |

### What the obligation is

| field | type | notes |
| --- | --- | --- |
| `direction` | enum | `issue` \| `receive`. Which way the obligation runs. |
| `counterparty_scope` | enum | `b2b` \| `b2c` \| `b2g` \| `b2b-and-b2c` \| `cross-border-b2b` |
| `bound_party` | string | Prose: exactly who it binds, in the source's own terms |

### Size band — how the band is defined

A rule recorded without its threshold is **wrong, not incomplete**. All six fields are present on every row; `threshold_type: "none"` means the obligation genuinely has no size test.

| field | type | notes |
| --- | --- | --- |
| `threshold_type` | enum | `none` \| `turnover` \| `revenue_or_fees` \| `headcount` \| `entity_type` |
| `threshold_value` | number \| null | null iff `threshold_type` is `none` or `entity_type` |
| `threshold_currency` | string \| null | ISO 4217, or null |
| `threshold_operator` | enum \| null | `gt` \| `gte` \| `lt` \| `lte` \| `between`. Reads as *row applies when measured value `op` `threshold_value`*. |
| `threshold_basis` | string \| null | What quantity is measured, named as the instrument names it |
| `threshold_period` | string \| null | **Over what period it is measured.** "preceding calendar year" etc. A threshold without its period is not usable |
| `threshold_definition` | string \| null | The full definition, quoting the instrument where it matters |

### Format

| field | type | notes |
| --- | --- | --- |
| `format_name` | string | |
| `format_version` | string \| null | **A format name without a version is incomplete.** Peppol BIS, Factur-X, XRechnung and FatturaPA all have versions with their own cutover dates |
| `format_note` | string \| null | Profile exclusions, permitted alternatives, upcoming version cutovers |

### Dates — two of them, not one

| field | type | notes |
| --- | --- | --- |
| `mandatory_from` | date \| null | First date the obligation actually bites |
| `tolerance_ends` | date \| null | Last date a non-compliant alternative is still allowed. **Distinct from `mandatory_from`, and buyers care about both.** null means no tolerance exists |
| `tolerance_note` | string \| null | What exactly is tolerated, and on whose consent |

### Provenance — no orphan facts

| field | type | notes |
| --- | --- | --- |
| `legal_instrument` | string | Citation of the instrument the row comes from |
| `source_url` | string | **Required, never null.** A primary source: statute, gazette, tax authority, EU legal act, standards body |
| `source_title` | string | So a page can label its own proof link |
| `source_type` | enum | `statute` \| `tax_authority` \| `official_gazette` \| `eu_legal_act` \| `standards_body` \| `secondary` |
| `secondary_source_urls` | string[] | Corroboration and leads. May be empty. **Never the sole basis of a `verified` row.** |
| `checked_on` | date | **Required.** The date a human or agent last read `source_url` and confirmed the row |

### Doubt — carried in the data, never rounded off

| field | type | notes |
| --- | --- | --- |
| `confidence` | enum | `verified` (read from a primary source) \| `reported` (credible secondary only) \| `unknown` (recorded, not established) |
| `confidence_note` | string \| null | What was actually read, and when |
| `unknowns` | string[] | Named gaps **in this row**. Non-empty on a `verified` row is normal and expected: the date is solid, something adjacent is not |
| `notes` | string \| null | Anything a reader needs that no other field holds |

A row is never dropped for being uncertain and never promoted silently. `confidence` and `unknowns` are the fields that carry doubt.

## Rules a consumer can rely on

1. `obligation_id` is unique across the file. Duplicates are a build failure, not a warning.
2. `source_url`, `checked_on` and `confidence` are non-null on every row, always.
3. All dates are `YYYY-MM-DD`. No partial dates, no prose dates. Unknown date ⇒ `null` plus an `unknowns` entry.
4. Absence of a jurisdiction means not-yet-recorded. Never "no obligation".
5. Re-running `dataset/build.py` on the same input produces byte-identical output.

## Rendering guidance

- `confidence: "verified"` with empty `unknowns` → render the date plainly.
- `confidence: "verified"` with non-empty `unknowns` → render the date plainly, and surface the unknowns. The date is sound; a neighbouring fact is not.
- `confidence: "reported"` → attribute it. "Reported as …, not confirmed against a primary source."
- `confidence: "unknown"` → render as unknown. Do not fall back to a nearby row's date.
- Always show `checked_on`. A row is as good as its last check and no better.
- `tolerance_ends` present → say both dates. "Mandatory from X; paper accepted until Y" is the answer people need.

## Proposed for 1.1.0 — `threshold_is_live` (not in 1.0.0, do not code against it yet)

A known hole in 1.0.0, written down so nobody has to rediscover it. Phased rollouts leave **dead
thresholds** behind, and 1.0.0 gives a consumer no way to tell a dead one from a live one:

- Germany's €800k line is **live**: it genuinely decides whether an entrepreneur's issuing date is
  2027 or 2028, so it must be evaluated against the company's actual turnover.
- Italy's €25,000 line is **dead**: it only selected a commencement date (July 2022 above it,
  January 2024 below it). Both dates have passed, so *every* party in `bound_party` is now bound
  regardless of revenue. The figure is kept for the audit trail, not for filtering.

Both rows look identical in 1.0.0 — `threshold_type` plus a value and an operator. The consequence
today is that `IT-e-invoicing-b2b-issue-forfetario-residual` grades as `unresolved` on size-band
pages, because `threshold_type: "revenue_or_fees"` is not bandable against turnover. **That is the
correct render for now**: "we cannot size this against a turnover band" is true and harmless,
whereas filtering on a dead threshold would produce the worst possible output — a confident "this
does not apply to you" for someone it has bound since 2024.

1.1.0 will add `threshold_is_live` (bool) and `threshold_is_live_note` (string). `false` will mean
*do not filter on the threshold; the row binds everyone `bound_party` describes*. Additive, so
1.0.0 consumers keep working untouched.

## Schema evolution

Additive by default. New optional fields may appear in a `1.x` release and a consumer must ignore unknown keys. Renaming or removing a field, or changing the meaning of an enum value, requires a major version bump, a new filename (`obligations.v2.json`), and a migration note in `dataset/CHANGELOG.md`. The current file keeps serving until consumers have moved.

## Where it lives

| path | what |
| --- | --- |
| **`dataset/dist/obligations.json`** | **The dataset. This is the only path a consumer reads.** |
| `dataset/dist/obligations.csv` | Flattened snapshot, same 31 columns, derived. Do not hand-edit. |
| `dataset/schema/obligations.v1.schema.json` | JSON Schema for machine validation |
| `dataset/schema/v1.md` | This document — the contract |
| `dataset/sources/*.yaml` | Per-jurisdiction row sources, becoming the source of truth |
| `dataset/build.py` | Validates sources and generates everything in `dist/` |
| `dataset/CHANGELOG.md` | Dated diffs. Every change to a published row lands here |
| `dataset/sources/verification-log.md` | What was read, when, and what it said |

`dataset/dist/obligations.json` is the stable contract and will not move. Behind it, authoring is
migrating from a hand-maintained `dist/` to per-jurisdiction `sources/*.yaml` compiled by
`build.py` (see [ARC-3](/ARC/issues/ARC-3)). That migration changes the `generated_from` string and
nothing else a consumer touches — same path, same schema version, same columns.
